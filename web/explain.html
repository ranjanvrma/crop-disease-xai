How the model explains itself

01Three heatmap methods

All three are class activation maps: they weight the last convolutional layer's feature maps (for MobileNetV3, 960 maps of 7×7 cells) and add them up into one 7×7 map, which is enlarged to the 224×224 photo.

Grad-CAM
Weights each feature map by the average gradient of the class score with respect to it: "how much would the score rise if this pattern got stronger?"
Grad-CAM++
Uses second- and third-order gradient terms so that several separate lesions on one leaf can all light up, instead of only the strongest one. This is the method the app shows.
Score-CAM
Needs no gradients: masks the photo with each feature map in turn and measures how much the class score rises. Much slower (one forward pass per map).

02Grad-CAM++ without gradients

Phones and browsers run models forward only; they cannot compute gradients. But every network here ends in global average pooling followed by one linear layer, so the gradient of class score yc with respect to every cell of feature map Ak is the constant gk = Wc,k / (H·W). Grad-CAM++ then collapses to a closed form that needs only one forward pass.

αk = gk² / (2gk² + gk³ ΣijAkij + ε),  wk = HW · ReLU(gk) · αk,  Lc = ReLU(Σk wkAk)

We checked it against the standard pytorch-grad-cam library on every trained model: on maps scaled 0 to 1 the largest difference is about 0.000001, so the two are the same. The same formula runs in your browser on the Diagnose page (web/src/xai.js), and a parity test checks the JavaScript against the Python to 1e-4.

03Is a heatmap honest?

A heatmap can look convincing and still be wrong. We measure faithfulness: if the bright regions really drove the answer, removing them should hurt the model most.

What each metric means
Deletion AUC ↓
Remove pixels from brightest to darkest in 20 steps and track the class probability. A faithful map makes it collapse fast: small area under the curve.
Insertion AUC ↑
Start from a blurred photo and restore pixels from brightest to darkest. A faithful map makes the probability rise fast.
Average Drop ↓ / Increase in Confidence ↑
Show the model only the highlighted region: how much confidence is lost (or gained)?
ROAD ↑
Remove-and-debias: like deletion, but removed pixels are filled in from their neighbours, so the model is not just reacting to odd-looking holes.

The app runs a small live version of this on every photo: it hides the brightest 20% and a random 20%, and only says "Passes" if the bright area matters more.

04What compression does to the heatmaps

To run on cheap phones the baseline MobileNetV3 (mnv3_fe) was compressed with structured pruning (removing 50% or 70% of channels) and INT8 quantization. Does the compressed model still look at the same places? Each compressed model's heatmap is compared with the parent's on the same images (Spearman rank correlation; 1 = identical).

05Can we trust the confidence?

Expected calibration error (ECE) compares confidence with how often predictions are actually right. 0 means "80% confident" really is right 80% of the time.

This is why the app has a "Not sure" state: below a confidence threshold, tuned on the validation split only, it refuses to name a disease.

07Spotting photos it was not trained on

A classifier always answers with one of the classes it knows. Show it a cat and it will name a tomato disease, sometimes with high confidence, so the "Not sure" threshold alone does not catch it.

So the app also asks "does this photo look like anything in the training set?". It averages the network's feature maps into one number per channel (the same numbers the final layer uses), then measures how far that point is from the average of each of the 38 classes in the training photos, using the Mahalanobis distance (which accounts for how much the features normally vary and how they move together). If even the closest class is far away, the app shows "This doesn't look like a leaf from one of the supported crops" instead of a diagnosis. The check costs no extra model run: it reuses the features already computed for the heatmap.

Limits. This is a distance in the model's own feature space, so it only knows what the model learned to see. A leaf of an unsupported plant that looks like a supported one (for example another nightshade next to tomato) can pass, and a real field photo of a supported crop can be flagged, because field photos also look unlike the lab training photos. The threshold was set using lab validation photos only; the other photos were used only to measure it.
