How the model explains itself

A diagnosis alone is not enough: a farmer, or an examiner, needs to see why the model said it. For every photo the app draws a heatmap of the regions that pushed the model towards its answer, then tests whether that heatmap is honest. This page explains the methods, the checks, and what they revealed about the models.

1. Three heatmap methods

All three are class activation maps: they weight the last convolutional layer's feature maps (for MobileNetV3, 960 maps of 7×7 cells) and add them up into one 7×7 map, which is enlarged to the 224×224 photo.

Grad-CAM
Weights each feature map by the average gradient of the class score with respect to it: "how much would the score rise if this pattern got stronger?"
Grad-CAM++
Uses second- and third-order gradient terms so that several separate lesions on one leaf can all light up, instead of only the strongest one. This is the method the app shows.
Score-CAM
Needs no gradients: masks the photo with each feature map in turn and measures how much the class score rises. Much slower (one forward pass per map).

2. Grad-CAM++ without gradients

Phones and browsers run models forward only; they cannot compute gradients. But every network here ends in global average pooling followed by one linear layer, so the gradient of class score yc with respect to every cell of feature map Ak is the constant gk = Wc,k / (H·W). Grad-CAM++ then collapses to a closed form that needs only one forward pass:

αk = gk² / (2gk² + gk³ ΣijAkij + ε),  wk = HW · ReLU(gk) · αk,  Lc = ReLU(Σk wkAk)

3. Is a heatmap honest?

A heatmap can look convincing and still be wrong. We measure faithfulness: if the bright regions really drove the answer, removing them should hurt the model most.

Deletion AUC ↓
Remove pixels from brightest to darkest in 20 steps and track the class probability. A faithful map makes it collapse fast: small area under the curve.
Insertion AUC ↑
Start from a blurred photo and restore pixels from brightest to darkest. A faithful map makes the probability rise fast.
Average Drop ↓ / Increase in Confidence ↑
Show the model only the highlighted region: how much confidence is lost (or gained)?
ROAD ↑
Remove-and-debias: like deletion, but removed pixels are filled in from their neighbours, so the model is not just reacting to odd-looking holes.

The app runs a small live version of this on every photo: it hides the brightest 20% and a random 20%, and only says "Passes" if the bright area matters more.

4. What compression does to the heatmaps

To run on cheap phones the baseline MobileNetV3 (mnv3_fe) was compressed with structured pruning (removing 50% or 70% of channels) and INT8 quantization. We asked: does the compressed model still look at the same places? Each compressed model's heatmap is compared with the parent's on the same images (Spearman rank correlation; 1 = identical).

5. Can we trust the confidence?

Expected calibration error (ECE) groups predictions by confidence and compares the confidence with how often they were actually right. 0 means "80% confident" really is right 80% of the time.

This is why the app has a "Not sure" state: below a confidence threshold, tuned on the validation split only, it refuses to name a disease.
